# Sampler and quantized performance

Historical POC record. Current behavior and supported APIs are documented in [README.md](README.md).

## Outcome

Separate reusable sampler and musical sequence engines, integrated with the existing tracker in one AudioWorklet. A performance page prepares a sample bank, fires immediate one-shots, queues patterns for the next beat or bar, sets the next beat as 1, controls configured or live-following tempo, and stops all playback. Keyboard-emulating pedals and arcade controls use the same command bindings. Existing visual sequencer and tracker demos keep working.

First version uses whole-beat pattern steps and finite samples recorded from the microphone or loaded from files. No loops, time stretching, or inferred song downbeats. Three initially empty sample slots support immediate and quantized recording start/stop, then immediate and quantized playback. Operator states are Ready, Queued, Playing, with diagnostics available only through metadata/developer mode.

## Design choice

Both independent designs prefer a shared worklet over browser lookahead scheduling. Future starts scheduled on the main thread cannot track the final live-adjusted crossing under a stalled UI. BeatProcessor remains the only beat authority. SampleEngine owns PCM and voices. AudioSequenceEngine owns pattern positions, a single pending replacement, and explicit bar origin. The performance worklet composes them. Libraries remain independent of the operator page.

## Public modules and ownership

Sampler owner owns lib/sampler/{index.js,sample-engine.js,sampler.js,audio-endpoint.js,sampler-worklet.js,tests/*,package.json}. Sequencer/runtime owner owns lib/sequencer/{audio-sequence-engine.js,audio-sequencer.js}, generic BeatProcessor extension hooks and BeatTracker creation options, lib/sampler/web/performance-worklet.js, and rendered integration tests under lib/sequencer/tests. UI owner owns lib/sampler/web/{index.html,demo.css,demo.js,bank.js}, README.md, and docs only. No shared file writes.

AudioEndpoint owns a MessagePort, request IDs, promises, and state subscriptions. request(command, payload={}, transfer=[]) sends {id,command,payload}; replies are {id,ok,value?,error?,state?}. Unsolicited {state} is allowed. A state is {sampler,sequencer?}. Endpoint emits state before resolving replies. subscribe(listener) returns detach and immediately supplies latest known state if present. snapshot() returns latest state. dispose() rejects pending requests and closes its port. Endpoint may poll `state` every 50ms for UI metadata, with at most one outstanding poll; this never drives rendering. Allow pollInterval:0 for tests. Start the port on construction.

Sampler constructor({audioContext,endpoint}) attaches to a shared runtime. Methods load(id,AudioBuffer), loadPCM(id,channels,sampleRate), loadURL(id,url), loadFile(id,file), trigger(id,{gain=1,when=audioContext.currentTime}={}), setVolume(value), stopAll(), snapshot(), subscribe(listener), dispose(). These methods return acknowledged promises. Snapshot fields ready,samples,activeVoices,volume,metadata. Standalone static Sampler.create({audioContext}={}) uses sampler-worklet.js with stereo output; externally supplied contexts remain caller-owned. Attached sampler never closes a shared endpoint/context on disposal; standalone sampler owns its node/endpoint and closes an internally created context. Commands sample.load {sampleId,channels:Float32Array[],sampleRate}, sample.trigger {sampleId,gain,when}, sample.volume {volume}, sample.stopAll, state. Float32 PCM is copied before transfer so caller buffers remain valid. Decode uses the shared AudioContext.

SampleEngine constructor({sampleRate,maxVoices=32}): load(id,channels,sourceRate), has(id), trigger(id,frame,gain=1), setVolume(value), stopAll(), render(outputs,frameStart,outputOffset,length), snapshot(). Render adds to existing output, supports mono/stereo and linear sample-rate conversion, and has bounded preallocated voices. Later starts use absolute engine-frame timestamps; late starts clamp to the next unrendered frame. No object allocation per sample. Voice stealing and lateness are metadata. Validate PCM once on load. Voice/memory allocation is allowed in load/control handlers, not render.

AudioSequencer constructor({endpoint}), define(pattern), queue(id,{quantize:'beat'|'bar'}={quantize:'bar'}), cancelQueue(), markOne(), stopAll(), snapshot(), subscribe(listener), dispose(). Methods acknowledged promises, attached wrapper does not own endpoint. Commands sequence.define {pattern}, sequence.queue {patternId,quantize}, sequence.cancel, sequence.markOne, performance.stopAll. Pattern {id,label,lengthBeats,events:[{atBeat,sampleId,gain?}]}; positions nonnegative integers less than lengthBeats. Queue replaces the single pending request. Launch replaces the active pattern on the qualifying crossing. Completed sample tails can overlap; Stop All clears voices, pending launch, and active pattern atomically.

AudioSequenceEngine constructor({beatsPerBar=4,play,hasSample}), define(pattern), queue(id,quantize), cancelQueue(), markOne(), stop(), reset(beatId=0), onBeat(id,frame,epoch), snapshot(). play(sampleId,frame,gain) invokes SampleEngine. hasSample validates references before accepting a pattern. First actual crossing establishes initial beat 1. markOne marks the next crossing as a new bar 1, without changing tracker phase/tempo. Recompute pending bar target from the new origin; a queued bar launch can start on that marked crossing. Queues retain beat serial targets rather than future milliseconds, so all future pattern hits follow actual crossings. Existing patterns keep their relative beat progression when bar origin changes. Reset/epoch invalidates both active and pending playback.

Sequencer snapshot {status:'ready'|'queued'|'playing',playing:null|{id,label,positionBeat,lengthBeats},queued:null|{id,label,quantize,targetBeatId},bar,beat,beatsPerBar,patterns:[{id,label,lengthBeats}],metadata}. queued may coexist with currently playing. Sequence callbacks and sample onset do not depend on browser polling. Existing Sequencer class remains the callback-based non-audio path; no duplicate detector clock is introduced.

## Tracker integration

Export BeatProcessor while retaining registerProcessor('beat-tracker',BeatProcessor). Add generic initializeOutput(options), onBeat(id,frame,epoch), renderOutput(output,offset,begin,end,frameStart), onTimelineReset(epoch,beatId), disposeOutput() hooks. initializeOutput runs before the constructor's ready reply so subclasses can initialize safely. Default renderOutput renders the existing click. All clock events reach onBeat exactly once, including drains during reply(). Render segments around actual crossing frames, using ceil for the first output sample at/after a fractional crossing. Call onBeat before rendering the following segment. Output is zeroed once per block, then click and sample mixing add to it. Hook defaults have no sampler dependencies.

BeatTracker.create adds processorName='beat-tracker', processorOptions={}, and outputChannels=1 options. WASM module remains authoritative in processorOptions. Existing defaults remain unchanged. The performer selects processorName='performance', outputChannels=2, and its own workletUrl.

PerformanceProcessor in lib/sampler/web/performance-worklet.js imports BeatProcessor, SampleEngine, AudioSequenceEngine. initializeOutput creates engines. receive({type:'performance-connect',port}) attaches a transferred dedicated port, leaving tracker.node.port exclusively owned by BeatTracker. Port commands route to the engines and always return request acknowledgments or clear errors plus current state. `when` context seconds converts to engine frames via when*sampleRate-frameOrigin, clamped at processedFrames when late. renderOutput calls base click rendering then mixes SampleEngine. onBeat calls AudioSequenceEngine. Timeline reset and disposal stop both engines. Polling state returns snapshots; no polling is needed for execution.

The application creates MessageChannel, transfers one end with tracker.node.port.postMessage({type:'performance-connect',port:channel.port2},[channel.port2]), and constructs one AudioEndpoint(channel.port1), Sampler({audioContext:tracker.context,endpoint}), and AudioSequencer({endpoint}). Standalone sampler node uses its own node.port directly as endpoint.

## Operator controls

Prepare enables audio and preloads bank once. Three immediate pads use A/S/D. Pattern buttons use J/K/L and a Beat/Bar quantization choice. Stop All uses Escape. Next beat is 1 uses Digit1. Tap tempo uses T or a keyboard-emulating pedal. Manual and Follow remain explicit; tap/manual takeover persists until Follow. Volume and BPM are editable controls. A microphone meter and honest Listening/Following/Coasting indication show input/clock health. Keep implementation details hidden. Use one registry for command bindings and displayed shortcut labels. UI action errors are visible; pending setup/actions are disabled or guarded against duplicate activation.

## Throughput checkpoint

- Blocking steps. Inspect existing timing paths and compare scheduling alternatives before editing.
- Independent workstreams. Sampler core/client, sequencer/audio integration, and operator page have distinct file owners after this contract.
- Shared state. One AudioEndpoint owns the dedicated port; one worklet owns each audio engine and the clock. Files have single writers.
- Smallest safe decomposition. Three implementers share this fixed protocol; coordinator integrates, reviews, and drives the browser.

## Verification

Render actual WASM clock plus PCM through the performer processor. Check exact onset frames, next-beat/bar launch, queue replacement/cancellation, Mark 1, tempo changes, coasting, reset invalidation, immediate hits, overlapping/stereo/rate-converted audio, Stop All tails, and analyzer isolation. Run with no UI polls for several seconds. Keep existing tracker and sequencer suites passing. Verify the real operator page with keyboard and mouse. Do not claim physical hardware, microphone tracking, or output-device latency measurements without testing them.


## Microphone sampling correction

The operator clarified that sampling means capturing microphone audio, not only loading existing audio. This is required in the same sampler, with per-slot record start and stop both immediate and quantized. Each completed take replaces that slot's previous sample. Existing preloaded/file playback remains a library capability, but the operator page begins with three empty slots.

Sampler owner adds lib/sampler/sample-recorder.js exporting SampleRecorder. Constructor({sampleRate,sampler,maxSeconds=30,maxSlots=8}). prepare(sampleId,{maxSeconds}={}) allocates a bounded mono recording buffer in the message/control handler, before an armed start reaches the audio callback. start(sampleId,frame) starts a prepared take; stop(sampleId,frame,reason='stopped') installs captured PCM into SampleEngine if nonempty. capture(input,inputOffset,length,frameStart) copies only the segment while recording, with no allocation per sample or per segment. stopAll(reason) commits active takes. snapshot() returns recording slot records {id,recording,frames,duration,maxSeconds,peak,reason}. Recordings auto-stop at their bound and become playable. The previous take remains until a nonempty new take commits. Use a trusted internal SampleEngine install method for captured finite PCM, without scanning/copying the entire recording on a beat crossing. All captured audio remains browser-local and never directly monitors to output.

Sampler client adds startRecording(id,{maxSeconds=30}={}) and stopRecording(id), using record.start {sampleId,maxSeconds} and record.stop {sampleId}. Sampler snapshots add recordings from the recorder. Standalone worklet supports one mono input and recording, with externally owned sources connected to sampler.node; standalone does not own or automatically acquire a microphone. The performance app's tracker already owns its microphone stream.

Sequencer owner extends AudioSequenceEngine with optional recorder capabilities prepareRecording(id,options), startRecording(id,frame), stopRecording(id,frame), isRecording(id). Existing nonrecording constructor callers remain valid. Add armRecording(id,{action:'start'|'stop',quantize='bar',maxSeconds=30}), cancelRecording(id), cue(sampleId,{quantize='bar',gain=1}), cancelCue(id). Record arming is a single pending start/stop per slot. One-shot playback cues are independent per slot, replacing only that slot's pending cue. Pattern launch remains one global pending replacement. All targets use the existing actual beat serial and common bar origin; Mark 1 reanchors pending bar targets for recording and playback too.

On each actual crossing, process due recording commands first, then per-slot one-shot cues, then pattern hits. Stopping a take on a crossing therefore makes it available before any playback dispatched on that crossing. Queueing playback requires a completed take; live overdub playback is outside the first version. Immediate record start/stop cancels that slot's pending recording arm. Starting a take while already recording rejects clearly. Stopping when no take is recording can be a no-op after canceling an arm. Canceling an arm does not stop an active take.

Dedicated commands: record.start, record.stop, sequence.record {sampleId,action,quantize,maxSeconds}, sequence.recordCancel {sampleId}, sequence.cue {sampleId,quantize,gain}, sequence.cueCancel {sampleId}. Performance Stop All cancels pattern launches, sample cues, and recording arms, stops/commits current recordings, and silences voices atomically. Timeline resets clear queued actions and commit active recordings before clearing output. Sequencer snapshot adds recordArms:[{sampleId,action,quantize,targetBeatId}] and cues:[{sampleId,quantize,targetBeatId}]; status queued includes pending sample cues, while recording state is represented explicitly in per-slot controls.

Base processor's segmented hook changes from renderOutput to processAudio(input,output,offset,begin,end,frameStart). Existing default still renders the click. Each segment receives the original mono input, before/after the clock crossing in exactly the same order as rendering. Performer processAudio captures input via recorder.capture(input,offset+begin,end-begin,frameStart+begin), then renders click and mixes playback. The standalone sampler captures its input before mixing its output. Exact capture begins at ceil(start crossing) and ends before ceil(stop crossing). Input PCM never includes the sampler's output internally.

Operator page Prepare enables audio and requests the microphone, keeping tempo Manual until Follow is selected. Show three empty Sample A/B/C slots with capture state and duration. Per slot provide Record now/Stop now, Arm start/Arm stop with cancellation, Play now, and Cue playback. Global Beat/Bar choice applies when a recording/playback arm is submitted, and the slot shows its selected pending action. Suggested bindings: play A/S/D, cue Q/W/E, immediate recording toggle Z/X/C, armed recording toggle V/B/N; Tap T, Follow F, Manual M, next beat 1, Stop All Esc. Keep one command registry. Disable playback of a slot while recording or arming start. Preset sequences remain available only once their referenced slots contain completed samples, defined lazily after recording/file load. Do not load synthetic demo sounds by default. Optional file load is available when performance is idle. Contextual headphones guidance while recording is an operator need.

Required regression gates include actual input ramp capture with immediate boundaries, quantized start/stop at beat/bar, duration limit auto-stop, no sample monitoring, saved PCM playback both immediate and quantized, per-slot independent queues, queued recording and Stop All cancellation, Mark 1 reanchoring all armed targets, and full existing suite coverage. Root coordinates new method contracts and real browser verification.
