# Parallel scene production

Split work by the artifact another lane can consume. Keep one current handoff using [the existing record](handoff-record.md); this guide adds production decisions, not a new runtime schema.

## Divide the work

| Lane | Starts from | Returns | Dependency |
| --- | --- | --- | --- |
| Character art | Selected identity reference | Finished neutral, native grid, pivot, Body/Effects sources, actual export and bound reviews | Needed before production pose expansion |
| Motion exploration | Approved model or explicitly labelled concept | Starting/contrasting poses, then held-pose options and remaining gaps | Early concepts can proceed during neutral finishing; final drawings use the frozen master |
| Scene blocking | Current stage, camera and known contact/occlusion surfaces | Action endpoints in each required aspect | Can use a clearly labelled stand-in while an unrelated character is being finished |
| Effects and scene states | Separate setting/FX layers | Bounded effect-on/off or start/end studies with exposed parameters | Does not require body redraws; do not bind deferred musical cues |
| Integration and review | The lanes' current handoffs | Actual Figma composition/export, next operator decision, compact current references | Shared-file calls follow the project's existing ownership/lease harness |

Give source edits, code edits and preparation separate owners and locations. Parallel preparation does not authorize simultaneous writes to a shared Figma file. Follow the current project lease guide and caller; do not invent another lock or bypass recovery. Independent headless preparation may continue while a shared-file operation is held.

## Deliver small review units

Name each job's next visible artifact and its exact input dependency. Return a first bounded pose or endpoint study before expanding it into a complete family. Do not delay a completed cow comparison behind an unrelated bedroom refactor. Integrate finished units as they arrive instead of waiting for every lane to finish.

Model approval, native pixel finishing, action approval, tween timing and runtime promotion remain separate decisions. A selected concept authorizes its faithful finishing; a finished neutral does not approve new actions. When the operator wants endpoint approval before tweening, submit that endpoint and work on independent jobs while awaiting the answer.

Keep the script and its explicit bar landmarks in the shared authoring store. Preserve verbatim input and append confirmed corrections rather than silently repairing a range or overlap. When cues and timing are deferred, use provisional review seconds and keep musical bindings open. Share proposed work as a queue with known prerequisites, not as invented casting, controls or performance behavior.

## Reuse scene structure

Separate layers by what must move independently. In a bedroom, sky, moon, room including the nightstand, actor, and bed foreground may need that exact order. Keep an actor's internal support and blanket overlap intact inside the composition. A source image split is not complete merely because its recomposition matches: inspect the layer contents so moving the moon does not carry stars or curtains with it.

Reuse observed pixels for a bounded split. State any inferred material needed behind an opaque object and constrain it to that footprint. Compare the actual recomposed baseline and protected pixels. Do not describe inferred hidden fill as recovered original art.

Keep fit, actor scale and placement explicit per aspect. A 4:3 view may need a different reframe or actor size. For a fractional display scale, use verified nearest-neighbour presentation from the unchanged master when appropriate; inspect the actual result for blur, support and occlusion. Do not redesign the character to correct scene scale.

## Use the right proof and stop repeating it

Review the actual source and actual composed export. Correct source pixels cannot prove visible scale, layer order or camera registration. Conversely, a protected-pixel comparison can pass while an actor is invisible or tiny. Inspect the whole scene plus a useful native/integer crop.

Check text and image layout in the actual review-board export. A successful node creation or populated image hash does not prove readable labels or unclipped artwork. Use measured or explicit text boxes when unsettled font metrics return misleading dimensions.

Bind reviews to current artwork and reference hashes. Reuse passing evidence for unchanged scope; re-run the affected checks after an edit. Grid alignment, palette counts and export equality do not replace identity, anatomy, motion-intent or artistic review. Keep the question “Is this the work of a mid-res 8-bit pixel artist?” for finished drawings.

Run preparation before mutation and check its completed success. If transport creation fails, do not invoke the downstream command with an absent file. For shared-state commands use the normal API, fresh identity/revision checks and operation receipt; hand harness uncertainty to the assigned recovery owner without replaying or replacing the wrapper. Hold dependent work only.

## Keep the current review clear

Put selected masters, current options and their next decisions in Figma. After actual readiness and consumer checks, retire the exact superseded drawings and temporary scene copies. Unknown consumers hold that deletion, not unrelated production. Keep concise source IDs, hashes and decisions; retain active evidence until the canonical handoff is verified, then let process debris expire under the project's retention policy.
