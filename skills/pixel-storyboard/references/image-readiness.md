# Upload before replacing a visible actor

A failed Tribulations image upload left a newly created component blank. Replacing the visible actor before checking that fill made the actor disappear. DYC separately showed that correct source pixels and reported instance bounds can coexist with stale, tiny rendered geometry. Source readiness and actual placed visibility are separate checks.

Keep the existing actor while creating, uploading and filling the replacement source. Under the current exact Figma lease, run a read-only source snapshot generated by `scripts/video-expansion/figma-image-readiness.ts` in the show-tools checkout. Load the current Figma skills first. Use exact source page, component and image-filled node IDs.

```ts
import { readFile, writeFile } from 'node:fs/promises';
import { imageSourceSnapshotCode, prepareImageReplacementGuard } from './scripts/video-expansion/figma-image-readiness.ts';

const target = { fileKey, pageId: sourcePageId, sourceNodeId, imageNodeId };
const snapshotCode = imageSourceSnapshotCode(target);
// Execute snapshotCode through use_figma; save its COMPLETE response as source-response.json.
const response: unknown = JSON.parse(await readFile('source-response.json', 'utf8'));
const gate = await prepareImageReplacementGuard({
  target, response, expectedPng: await readFile('registered-source.png'), replacementPageId,
});
await writeFile('replace.js', gate.code + '\n' + authorizedReplacementCode, { flag: 'wx' });
await writeFile('source-ready.json', JSON.stringify(gate.receipt), { flag: 'wx' });
```

`registered-source.png` is the exact intended source canvas, including transparency and registration. Verify its input hash against the current art handoff. The helper checks a populated visible image fill inside the intended component, nonempty artwork and every decoded source RGBA pixel. A missing/DNS-failed upload, blank export, wrong file or page, invalid response or pixel mismatch cannot produce a replacement guard. It neither approves new artwork nor repaints a failed candidate.

Execute the entire guarded replacement script sequentially under the exact lease. The guard checks file identity first, switches once to `replacementPageId`, resolves the source afresh and compares its current image hash, dimensions and exact PNG export with the verified snapshot before any replacement mutation. The source may live on a different page; do not add a second page switch to the call. A failed or oversized transport returns to the harness owner; do not omit or truncate the guard. A stale guard requires a fresh snapshot and pixel comparison, not a waived check.

The guard does not create, hide, replace or delete nodes itself. The existing authorized replacement code still owns exact actor IDs, transforms, output IDs and cleanup. After replacement, export the actual composed scene and inspect visible actor size, position, contact and framing in each requested aspect ratio. Source parity alone cannot pass that delivery check. Preserve the prior valid source/export until this final check passes; correct or restore a failed placed candidate within the existing bounded authorization.

Record source readiness, actual placement review, art/style review and runtime promotion separately. Keep current receipts with active work; no permanent raw-upload archive is required. Run the focused regression with `node --import tsx --test scripts/tests/figma-image-readiness.test.ts`.
